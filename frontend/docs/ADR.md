| Foundation                   | Vite with React 19 and JavaScript                                                                    | Create React App or TypeScript from day one                  | Vite is required by the brief, is actively maintained, and keeps setup simple. ## Full ADR 001 Browser-only service boundary

### Status

Accepted for Milestone 1.

### Context

TuneTown must behave like an asynchronous shop while using no server, database, or external API. Components also must not read JSON or browser storage directly.

### Decision

All persistent reads and writes pass through one local Promise-based data service. A storage adapter handles versioned structured records, while the public service applies validation, delays, simulated failures, business rules, logging, and cross-tab events.

### Alternatives

Direct component storage access would require less initial code but would duplicate parsing and error handling across the app. A mock HTTP server would resemble a real backend but violates the no-server constraint and adds setup unrelated to the learning goals.

### Consequences

The UI can practice real loading, error, retry, and race-condition behavior. The service requires thorough tests because it becomes the authority for catalogue, stock, orders, reviews, and addresses.
